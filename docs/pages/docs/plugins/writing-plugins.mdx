If you've ever written a `webpack` plugin it's a lot like that.

A plugin definition is:

- a name for the plugin, should match the [name of the package](../configuration/plugins#plugin-declaration) (REQUIRED)
- a class the has an `apply` function where a plugin hooks into various functions in auto (REQUIRED)

You can write a plugin directly in TypeScript with no build step:

```ts
import { Auto, IPlugin } from "auto";

export default class TestPlugin implements IPlugin {
  name = "test";

  /** Tap into auto plugin points. */
  apply(auto: Auto) {}
}
```

Or in JavaScript:

```js
module.exports = class TestPlugin {
  constructor() {
    this.name = "test";
  }

  /**
   * Tap into auto plugin points.
   * @param {import('@auto-it/core').default} auto
   */
  apply(auto) {}
};
```

## Hooks

Plugins work by hooking into various actions that `auto` has to do in order to facilitate a release or interact with your GitHub repo.

[Read more about using hooks](./hook-api-docs)

## Adding Options

Most plugins will find the need to some some options from the user.
The constructor of the plugin gets access to the options passed in the `.autorc`.

```ts
import { Auto, IPlugin } from "@auto-it/core";

interface TestPluginOptions {
  someOption?: boolean;
}

export default class TestPlugin implements IPlugin {
  /** The name of the plugin */
  name = "test";

  /** The options of the plugin */
  readonly options: TestPluginOptions;

  /** Initialize the plugin with it's options */
  constructor(options: TestPluginOptions) {
    this.options = options;
  }
}
```

### Validation

`auto` validates the options passed to a plugin with the plugin's **options schema**.
`validatePluginConfiguration` accepts any [Standard Schema](https://standardschema.dev), so you can write it with [Zod](https://zod.dev), [Valibot](https://valibot.dev), [ArkType](https://arktype.io) or any other library that implements the standard.
`auto`'s own plugins use Zod.
Your options are defined once, and you get both the TypeScript type and runtime validation from it.

First install Zod:

```bash
npm i --save zod
# or
yarn add zod
```

Then write your options as a schema and derive the type from it.

```ts
import { z } from "zod";

const pluginOptions = z
  .strictObject({
    someOption: z.boolean(),
  })
  .partial();

export type TestPluginOptions = z.infer<typeof pluginOptions>;
```

Two rules for options schemas:

- **Reject unknown keys in the schema.** Use `z.strictObject` (or your library's strict equivalent). `auto` reports whatever your schema reports, so with a plain `z.object` a typo in a user's config is silently ignored.
- **Validate, don't transform.** `auto` only checks the options. Your plugin receives the options exactly as the user wrote them, so `.default()` and `.transform()` have no effect. Apply defaults in your constructor instead.

Then tap into the `validateConfig` hook and use the `validatePluginConfiguration` utility.

```ts
import { validatePluginConfiguration } from "@auto-it/core";

export default class MyPlugin implements IPlugin {
  // ...
  apply(auto: Auto) {
    auto.hooks.validateConfig.tapPromise(this.name, async (name, options) => {
      if (name === this.name || name === `auto-plugin-${this.name}`) {
        return validatePluginConfiguration(this.name, pluginOptions, options);
      }
    });
  }
}
```

And that's it!
Now `auto` will validate your plugins configuration before running.

If a plugin passes something that isn't a Standard Schema, such as an io-ts codec, `auto` logs a warning and doesn't validate that plugin's options.

### Migrating plugins to v12

Before v12, `validatePluginConfiguration` took an [io-ts](https://github.com/gcanti/io-ts) codec.
v12 takes a Standard Schema instead, and io-ts doesn't implement the standard.
To migrate, rewrite your options schema with Zod (or another Standard Schema library), then replace `io-ts` and `fp-ts` in your plugin's dependencies with `zod`.
Your `validateConfig` tap doesn't change.

Here's the same options schema before and after.

```ts
// Before: io-ts
import * as t from "io-ts";

const requiredOptions = t.interface({
  /** The URL to post to */
  url: t.string,
});

const optionalOptions = t.partial({
  /** Who to mention in the post */
  atTarget: t.union([t.string, t.boolean]),
  /** The smallest release to post about */
  threshold: t.keyof({ patch: null, minor: null, major: null }),
  /** Files to attach to the post */
  files: t.array(t.string),
});

const pluginOptions = t.intersection([requiredOptions, optionalOptions]);

export type MyPluginOptions = t.TypeOf<typeof pluginOptions>;
```

```ts
// After: Zod
import { z } from "zod";

const pluginOptions = z.strictObject({
  /** The URL to post to */
  url: z.string(),
  /** Who to mention in the post */
  atTarget: z.union([z.string(), z.boolean()]).optional(),
  /** The smallest release to post about */
  threshold: z.enum(["patch", "minor", "major"]).optional(),
  /** Files to attach to the post */
  files: z.array(z.string()).optional(),
});

export type MyPluginOptions = z.infer<typeof pluginOptions>;
```

| io-ts                                 | Zod                                       |
| ------------------------------------- | ----------------------------------------- |
| `t.type({...})`, `t.interface({...})` | `z.strictObject({...})`                   |
| `t.partial({...})`                    | `z.strictObject({...}).partial()`         |
| `t.intersection([A, B])`              | `A.extend(B.shape)`                       |
| `t.union([...])`                      | `z.union([...])`                          |
| `t.literal(x)`                        | `z.literal(x)`                            |
| `t.keyof({ a: null, b: null })`       | `z.enum(["a", "b"])`                      |
| `t.array(X)`, `t.tuple([...])`        | `z.array(X)`, `z.tuple([...])`            |
| `t.record(t.string, X)`               | `z.record(z.string(), X)`                 |
| `t.string`, `t.boolean`, `t.number`   | `z.string()`, `z.boolean()`, `z.number()` |
| `t.TypeOf<typeof X>`                  | `z.infer<typeof X>`                       |

A few things behave differently:

- **Unknown keys.** Before v12, `auto` rejected unknown keys for you, even when your codec used `t.type` or `t.partial`. Now your schema has to reject them, so use `z.strictObject`.
- **Error messages.** Some messages changed. For example, unknown keys are now reported together with other errors, not only when there are none, and some compound types are described more simply (`"tuple"` instead of `"[string, any]"`).
- **`labelDefinition`.** The `labelDefinition` export from `@auto-it/core` is now a Zod schema. Replace `labelDefinition.decode(value)` with `labelDefinition.safeParse(value)`.

## Example Plugin - NPM (simple)

To create a plugin simply make a class with an `apply` method and tap into the hooks you need.

```ts
import * as fs from "fs";
import { promisify } from "util";

import { IAutoHooks, Auto, SEMVER, execPromise } from "auto";
import getConfigFromPackageJson from "./package-config";

const readFile = promisify(fs.readFile);

export default class NPMPlugin {
  public apply(auto: Auto) {
    auto.hooks.getAuthor.tapPromise("NPM", async () => {
      const { author } = JSON.parse(await readFile("package.json", "utf-8"));

      if (author) {
        auto.logger.log.info("NPM: Got author information from package.json");
        return author;
      }
    });

    auto.hooks.getPreviousVersion.tapPromise("NPM", async () => {
      const { version } = JSON.parse(await readFile("package.json", "utf-8"));

      auto.logger.log.info(
        "NPM: Got previous version from package.json - ",
        version
      );

      if (version) {
        return auto.prefixRelease(
          JSON.parse(await readFile("package.json", "utf-8")).version
        );
      }
    });

    auto.hooks.getRepository.tapPromise("NPM", async () => {
      auto.logger.log.info("NPM: getting repo information from package.json");
      return getConfigFromPackageJson();
    });

    auto.hooks.publish.tapPromise("NPM", async (version: SEMVER) => {
      await execPromise("npm", [
        "version",
        version,
        "-m",
        "Bump version to: %s [skip ci]",
      ]);
      await execPromise("npm", ["publish"]);
      await execPromise("git", [
        "push",
        "--atomic",
        "--follow-tags",
        "--set-upstream",
        auto.remote,
        "$branch",
      ]);
    });
  }
}
```
